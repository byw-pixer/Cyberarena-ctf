# WEB-01 «Школьный портал» (100 баллов, Web, лёгкая)

**Размещение:** отдельный Docker-контейнер `lab-web`, доступен по `http://localhost:8080/lab/`.
**Флаг (демо):** `CTF{idor_open_door_42}`. Задаётся переменной `WEB01_FLAG` в `.env`, читается только контейнером лаборатории.

## Условие для участников
Школьный портал заметок. Вы вошли как student3 и видите свою заметку. Разработчики оставили на портале закрытую
тестовую страницу с секретом. Найдите её и получите флаг. Работать только с лабораторией `/lab/`.

## Уязвимость
IDOR (небезопасная прямая ссылка на объект, ошибка разграничения доступа). Заметка открывается по номеру в адресе
`notes?id=N`, а сервер не проверяет, что заметка принадлежит текущему пользователю.

## Решение
1. Открыть `/lab/`: видна ссылка на «Заметку №3» (`notes?id=3`).
2. В адресной строке заметить параметр `id` и подставить соседние номера.
3. `notes?id=2` показывает чужую заметку (расписание консультаций), значит проверки владельца нет.
4. `notes?id=1` открывает «ТЕСТОВУЮ СТРАНИЦУ» администратора, в тексте флаг.
5. Сдать флаг на платформе.

## Как исправить (для разбора после турнира)
Перед выдачей заметки сравнить владельца с текущим пользователем и вернуть 403 при несовпадении. В коде это
помечено комментарием в `lab/app.py`, функция `_note`.

## Безопасность задания
- Уязвимость ограничена одним словарём в памяти: файлов, команд и базы данных приложение не трогает.
- Контейнер лаборатории: не от root, read-only файловая система, без сети платформы и без интернета.
- Флаг не лежит ни в коде, ни в данных платформы, только в переменной окружения контейнера лаборатории.

## Что проверено автоматически
`tests/test_tasks.py`: класс `Web01Tests` (главная и своя заметка без флага, `notes?id=1` отдаёт флаг,
неверные id дают 400/404, чтение файлов через пути невозможно). `scripts/check.sh`: задание решается через Nginx.
