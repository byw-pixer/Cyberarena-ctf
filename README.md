# CYBERARENA

Учебная CTF-платформа для внутренних соревнований по информационной безопасности. Преподаватель публикует задания,
участники находят флаги формата `CTF{...}` и отправляют их на сайте, система сама начисляет баллы и строит рейтинг.
Всё работает на одном ноутбуке, без облака и внешних сервисов.

## Быстрый старт

Для запуска нужен **Docker** (Docker Engine с Compose v2 или Docker Desktop). Git нужен, если получаете исходники командой `git clone`. При локальной сдаче откройте терминал в каталоге переданной версии проекта.

```bash
git clone https://github.com/byw-pixer/Cyberarena-ctf.git cyberarena
cd cyberarena
docker compose up -d --build --wait
docker compose ps
```

Платформа откроется на **<http://localhost:8080>**. При первом запуске она сама создаёт базу данных, учётную запись
администратора и три задания. Проверьте статус `healthy` у всех трёх сервисов. Сборка при первом запуске требует интернета, дальше проект работает офлайн.

### Вход администратора

- логин: **`teacher`**
- начальный пароль создаётся случайно и хранится в файле с правами `0600` внутри тома. Прочитайте его в приватном терминале командой `docker compose exec -T app cat /data/admin-bootstrap`.
- при первом входе задайте новый пароль длиной от 12 символов. После смены начальный файл удаляется, а прежние сессии отзываются.
- при заданном `ADMIN_PASSWORD` начального файла нет. Переменная служит для первого создания аккаунта и не сбрасывает существующий пароль.

В админке преподаватель создаёт, просматривает, редактирует и публикует карточки.
Для физического удаления скройте пользовательскую карточку и введите `DELETE`
в её отдельной форме. Карточки с попытками или решениями, а также встроенные
задания остаются в базе. Используйте скрытие, чтобы убрать их из каталога,
сохранив историю и рейтинг.

## Что умеет платформа

**Участник:** регистрация и вход, каталог заданий со статусом решения, страница задания с формой отправки флага,
личный кабинет с историей решений, таблица лидеров (при равенстве баллов выше участник с более ранним последним результативным решением).

**Преподаватель:** создание и редактирование заданий, публикация и скрытие, просмотр последних попыток и засчитанных решений,
сброс попыток и решений в демонстрационном окружении с явным разрешением.

| ID | Баллы | Категория | Суть |
|---|---|---|---|
| WEB-01 | 100 | Web | уязвимое приложение в изолированном контейнере (ошибка разграничения доступа) |
| WEB-02 | 150 | Web | анализ HTML и JavaScript учебной страницы |
| CRYPTO-01 | 150 | Crypto | расшифровка перехваченной записки |

## Управление

| Действие | Команда |
|---|---|
| Состояние сервисов | `docker compose ps` |
| Остановить / запустить | `docker compose stop` / `docker compose start` |
| Перезапуск (данные сохраняются) | `docker compose restart` |
| Логи (всех или одного сервиса) | `docker compose logs -f` / `docker compose logs -f app` |
| Остановить только лабораторию | `docker compose stop lab-web` |
| Возобновить лабораторию | `docker compose start lab-web` |
| Потребление RAM и CPU | `docker compose stats --no-stream` |

Пользователи, карточки, попытки и решения находятся в томе `db_data`. Для полного сброса демонстрации используйте новое имя проекта и свободный loopback-порт, например `CYBERARENA_PORT=18090 docker compose --env-file /dev/null -p cyberarena-demo-new up -d --build`. Прежние данные остаются в прежнем томе. Сброс только попыток и решений разрешён преподавателю при `DEMO_RESET=true` и имени Compose-проекта с префиксом `cyberarena-demo-`.

### Резервное копирование и восстановление

`backup.py` делает согласованный SQLite-снимок, проверяет его целостность и создаёт новый файл с правами `0600`. Во время ротации флагов сначала дождитесь, пока стек стабилизируется. При необходимости сохраните задаваемый через окружение `SECRET_KEY` отдельно в хранилище секретов.

```bash
umask 077
backup_dir=$(mktemp -d "$HOME/backups/cyberarena.XXXXXXXX")
snapshot=$(docker compose exec -T app python backup.py)
docker compose cp "app:$snapshot" "$backup_dir/cyberarena.db"
docker compose cp app:/data/task_flags.json "$backup_dir/task_flags.json"
# Скопируйте этот файл только если SECRET_KEY был сгенерирован автоматически.
docker compose cp app:/data/secret_key "$backup_dir/secret_key"
```

Храните комплект в приватном каталоге. Он содержит хеши пользователей, подписывающий ключ и материалы для восстановления заданий. Начальный пароль учителя резервировать не нужно.

Для проверки восстановления используйте **новый** Compose-проект. Следующие команды для Linux переносят файлы только в пустой том. Если ключ задавался окружением, исключите `secret_key` из списка для `tar` и укажите защищённый env-файл вместо `/dev/null`. В обоих случаях задайте прежний `ADMIN_USERNAME`, если он отличался от `teacher`.

```bash
export CYBERARENA_PORT=18091
docker compose --env-file /dev/null -p cyberarena-restore build app
tar -C "$backup_dir" -cf - cyberarena.db task_flags.json secret_key |
  docker compose --env-file /dev/null -p cyberarena-restore run --rm --no-deps -T \
    --entrypoint sh app -ec 'test ! -e /data/cyberarena.db; tar -xf - -C /data; chmod 600 /data/cyberarena.db /data/task_flags.json; if test -f /data/secret_key; then chmod 600 /data/secret_key; fi'
docker compose --env-file /dev/null -p cyberarena-restore up -d --build --wait
```

Сверьте количество записей, рейтинг, вход и ресурсы на восстановленной копии. Для возврата на прежнюю версию после миграции используйте согласованный комплект файлов **до** миграции и отдельный том. Существующий том турнира не удаляйте.

## Настройки через `.env`

Проект работает и без файла `.env`. Чтобы изменить настройки, скопируйте `.env.example` в `.env`, раскомментируйте
нужные строки и примените: `docker compose up -d`.

| Переменная | Что делает | Если не задана |
|---|---|---|
| `ADMIN_USERNAME` | логин администратора | `teacher` |
| `ADMIN_PASSWORD` | пароль администратора (от 12 символов) | случайный при первом запуске, в закрытом файле `/data/admin-bootstrap` |
| `SECRET_KEY` | ключ подписи сессий и хешей флагов (от 32 символов) | случайный, хранится в томе `/data` |
| `WEB01_FLAG`, `WEB02_FLAG`, `CRYPTO01_FLAG` | значения первого запуска или новой ревизии | случайные независимые значения |
| `FLAG_REVISION` | уникальная метка явной ротации набора | текущая ревизия |
| `CYBERARENA_PORT` | порт на loopback | `8080` |
| `DEMO_RESET` | разрешает преподавателю очистить попытки и решения | `false` |

### Ротация встроенных флагов

Штатный рестарт переиспользует закрытый манифест из тома. Изменение переменной флага с прежней ревизией останавливает инициализацию с понятной ошибкой, а записи и материалы остаются прежними. У встроенных карточек постоянные идентификаторы, и админка меняет заголовок, описание, категорию, баллы, сложность и публикацию. Флаг и ссылку на встроенный материал обновляет оператор при развёртывании. Для пользовательских заданий флаг по-прежнему меняется через админку и сохраняется в виде HMAC.

Для плановой ротации:

1. Создайте проверенную копию БД и манифеста.
2. Укажите новую `FLAG_REVISION` в приватном `.env`. Для каждой переменной флага задайте своё значение формата `CTF{...}` с латиницей, цифрами, дефисом и подчёркиванием либо оставьте её пустой для генерации нового значения.
3. Выполните `docker compose up -d --build --wait`. Зафиксируйте `healthy` у всех сервисов, проверьте новую ревизию на отдельном стенде. Попытки и решения прежней ревизии сохраняются.
4. При прерванной инициализации повторите запуск с теми же настройками. Манифест незавершённой ревизии обеспечивает повторное использование тех же значений.

Для перехода со старой версии на БД с известными демонстрационными значениями явно задайте новую ревизию после резервного копирования. Без неё при несовпадении старого хеша обновление остановится. Проверьте сопоставление встроенных карточек, если в старой версии меняли и заголовок с кодом, и ссылку на ресурс. Сохраните прежний `SECRET_KEY`; его смена требует отдельной миграции HMAC пользовательских заданий.

## Архитектура и безопасность

Новый Compose использует `nginx/compose.conf`. Файл `nginx/nginx.conf` сохранён для старых контейнеров, которые монтируют его по прежнему пути.

```
Браузер → Nginx (127.0.0.1:8080) ─┬─ /      → app (FastAPI + SQLite, volume db_data)   [app-net]
                                  ├─ /static/ → app (стили и файлы заданий)             [app-net]
                                  └─ /lab/  → lab-web (учебный WEB-01)                  [lab-net, internal]
```

### Две сети: зачем и почему это безопасно

Задание WEB-01 намеренно уязвимо, поэтому его нужно запереть так, чтобы взлом задания не давал доступа к платформе.

- **app-net**: Nginx и платформа. Наружу выходит только порт Nginx и только на `127.0.0.1`.
- **lab-net** (`internal: true`): Nginx и лаборатория. У этой сети нет выхода в интернет.

Контейнер `lab-web` подключён только к `lab-net`, поэтому он не видит платформу и её базу данных (нет общей сети и общего тома),
не имеет прямого маршрута к app, доступа в интернет или Docker Socket. Nginx подключён к обеим сетям. Он удаляет cookie при проксировании в лабораторию.
Дополнительные ограничения лаборатории: запуск не от root, корневая файловая система только для чтения (запись только в `/tmp`),
`cap_drop: ALL`, `no-new-privileges`, лимит 256 МБ RAM, 0.5 CPU и 100 процессов. Лаборатория получает только свой учебный материал через отдельный том `lab_flags` в режиме чтения. Том БД доступен только приложению. Если лаборатория остановлена или упала, Nginx отдаёт понятную страницу с кодом 503,
а платформа и рейтинг продолжают работать.

### Защита платформы

- пароли хранятся как **Argon2id**. SQLite хранит проверочные **HMAC-SHA256**. Исходные значения встроенных заданий нужны для генерации материалов и находятся в закрытом манифесте вне web-root;
- **CSRF-токены** во всех формах, сессионные cookie подписаны, имеют `HttpOnly` и `SameSite=Strict`. Сервер хранит хеш идентификатора сессии, ограничивает её восемью часами и отзывает при выходе либо смене пароля;
- права администратора проверяются **на сервере**, а не скрытием кнопок;
- баллы начисляются **один раз**: решение хранится с составным уникальным ключом (пользователь, задание),
  повторная отправка ничего не добавляет;
- **ограничение частоты**: 3 секунды между попытками на пользователя и задание, не больше 20 попыток в минуту на пользователя,
  а в Nginx общий лимит на `POST /login`, `/register` и отправку флагов (ответ 429);
- администратор при первом входе обязан сменить пароль; секреты (`SECRET_KEY`, пароль) не хранятся в репозитории;
- Swagger и OpenAPI отключены;
- флаги заданий после старта убираются из окружения веб-процесса платформы.

Ограничения: для недоверенных участников в реальной эксплуатации нужна дополнительная изоляция на уровне виртуальной машины;
HTTPS не используется, потому что сервис слушает только `localhost`; в Docker все участники приходят с одного адреса,
поэтому лимиты Nginx общие и щедрые.

## Тесты и проверка

```bash
pip install -r app/requirements.txt pytest httpx pyyaml    # один раз, лучше в виртуальном окружении
pytest -q                                                  # тесты backend, заданий, шаблонов и инициализации
python tests/check_stack.py                                # проверка запущенного стека (нужны Python 3 и Docker)
```

`check_stack.py` по умолчанию выполняет проверки чтения и возвращает код 2 при неполной проверке, если других дефектов нет. Для остановки лаборатории требуется `--stop-lab`, проект с префиксом `cyberarena-test-` или `cyberarena-demo-` и отдельный loopback-порт, опубликованный Nginx этого проекта. Полный сценарий с изменением данных запускается только с новым именем тестового проекта:

```bash
python tests/compose_e2e.py --project cyberarena-test-demo --port 18081
python tests/check_stack.py --project cyberarena-test-demo --base http://127.0.0.1:18081 --stop-lab
```

Для браузерной проверки добавьте к `compose_e2e.py` параметр `--firefox-bidi PORT` и запустите Firefox с временным профилем и `--remote-debugging-port PORT`. Укажите отдельный локальный порт WebDriver BiDi. Сценарий проверяет регистрацию, меню, ошибки форм и страницы на пяти ширинах. Ему требуется Node с поддержкой WebSocket.

**Офлайн после сборки:** `docker compose up -d --no-build --pull never --wait`. Сначала загрузите готовые образы или выполните онлайн-сборку. История предыдущего прогона находится в [чек-листе приёмки](tests/ACCEPTANCE_CHECKLIST.md). Сопоставление с оригинальным ТЗ, сценарий защиты и порядок переноса описаны в [отчёте повторной приёмки](docs/ACCEPTANCE_FOLLOWUP.md).

## Платформы

Нужен только Docker, скрипты не используются.

- **Linux:** Docker Engine с Compose v2. Подходит штатный системный или rootless daemon. Инструкция по доступу приведена в [документации Docker](https://docs.docker.com/engine/security/rootless/).
- **macOS:** Docker Desktop. Образы поддерживают Intel и Apple Silicon.
- **Windows:** Docker Desktop с бэкендом WSL 2 (режим Linux-контейнеров). Команды выполняются в PowerShell, cmd, Git Bash или WSL.
  При клонировании `.gitattributes` сохраняет в конфигах и Python-файлах переводы строк LF.

## Структура репозитория

```
├── compose.yaml            сервисы nginx, app, lab-web, сети, volume, лимиты
├── .env.example            необязательные настройки (все строки закомментированы)
├── app/                    платформа: main.py, models.py, init_db.py, task_files.py, backup.py, templates/, static/
├── lab/                    уязвимое приложение WEB-01
├── nginx/compose.conf      маршрутизация, ограничение частоты, страница 503
├── tests/                  автотесты, check_stack.py, чек-лист приёмки
└── docs/                   заметки по backend и описание дизайн-макета
```

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `docker: command not found` или `Cannot connect to the Docker daemon` | Docker не установлен или не запущен (Docker Desktop должен показывать «Engine running») |
| `port is already allocated` на 8080 | порт занят: для отдельной проверки в Bash выберите свободный порт и запустите `CYBERARENA_PORT=18127 docker compose -p cyberarena-demo-defense up -d --build --wait`, затем откройте `http://localhost:18127` |
| Не знаю пароль администратора | Для первого входа используйте приватный файл `/data/admin-bootstrap`. Если пароль уже менялся, переменная `ADMIN_PASSWORD` его не сбросит. Сохраните БД перед отдельной процедурой восстановления доступа. |
| `app` не запускается, в логе `ОШИБКА НАСТРОЙКИ` | значение в `.env` неверного формата: `SECRET_KEY` короче 32, `ADMIN_PASSWORD` короче 12 символов или флаг не в формате `CTF{...}` |
| После входа `Please change initial password` | сначала смените пароль на `/change-password` |
| Ошибка 429 при входе или отправке флага | сработало ограничение частоты, подождите около минуты |
| `/lab/` показывает 503 | контейнер лаборатории остановлен: `docker compose start lab-web`, причина в `docker compose logs lab-web` |
| Права на сокет Docker в Linux (`permission denied`) | Используйте штатный интерактивный `sudo` либо отдельный rootless daemon. |

Замечания по первоначальному дизайн-макету: [docs/DESIGN_MOCKUP.md](docs/DESIGN_MOCKUP.md).
