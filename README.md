# CYBERARENA

Учебная CTF-платформа для внутренних соревнований по информационной безопасности. Преподаватель публикует задания,
участники находят флаги формата `CTF{...}` и отправляют их на сайте, система сама начисляет баллы и строит рейтинг.
Всё работает на одном ноутбуке, без облака и внешних сервисов.

## Быстрый старт

Нужен только **Docker** (Docker Engine с Compose v2 или Docker Desktop). Больше ничего устанавливать и настраивать не требуется.

```bash
git clone <адрес-репозитория> cyberarena
cd cyberarena
docker compose up -d --build
```

Платформа откроется на **<http://localhost:8080>**. При первом запуске она сама создаёт базу данных, учётную запись
администратора и три задания. Сборка при первом запуске требует интернета, дальше проект работает офлайн.

### Вход администратора

- логин: **`teacher`**
- пароль: создаётся **случайным при первом запуске** и один раз печатается в лог. Чтобы его увидеть:

  ```bash
  docker compose logs app
  ```

  В начале вывода есть рамка из символов `=` с логином и паролем.
- при первом входе платформа **попросит сменить пароль** (не короче 12 символов).

Постоянного пароля в репозитории нет намеренно: по условиям задания начальная учётная запись не должна фиксироваться
публичным паролем. Если нужен свой пароль, задайте его в `.env` (раздел «Настройки через `.env`»).

## Что умеет платформа

**Участник:** регистрация и вход, каталог заданий со статусом решения, страница задания с формой отправки флага,
личный кабинет с историей решений, таблица лидеров (при равенстве баллов выше тот, кто решил раньше).

**Преподаватель:** создание и редактирование заданий, публикация и скрытие, просмотр последних попыток,
сброс результатов турнира.

| ID | Баллы | Категория | Суть |
|---|---|---|---|
| WEB-01 | 100 | Web | уязвимое приложение в изолированном контейнере (ошибка разграничения доступа) |
| WEB-02 | 150 | Web | анализ HTML и JavaScript учебной страницы |
| CRYPTO-01 | 150 | Crypto | расшифровка перехваченной записки |

## Управление

| Действие | Команда |
|---|---|
| Состояние сервисов | `docker compose ps` |
| Остановить / запустить | `docker compose stop` / `docker compose start` |
| Перезапуск (данные сохраняются) | `docker compose restart` |
| Логи (всех или одного сервиса) | `docker compose logs -f` / `docker compose logs -f app` |
| Убрать контейнеры (данные остаются) | `docker compose down` |
| Сбросить только результаты турнира | админка → «Сброс турнира» (ввести `RESET`) |
| Полный сброс: пользователи, решения, задания | `docker compose down -v` и затем `docker compose up -d --build` |
| Потребление RAM и CPU | `docker stats --no-stream` |

Пользователи и результаты хранятся в Docker volume `db_data` и сохраняются после `docker compose restart`.
Команда `down -v` удаляет этот том: после неё создаётся новая база и новый пароль администратора.

**Резервная копия SQLite** (платформа может работать):

```bash
docker compose exec app python backup.py
docker compose cp app:/data/backup.db ./backup.db
```

## Настройки через `.env`

Проект работает и без файла `.env`. Чтобы изменить настройки, скопируйте `.env.example` в `.env`, раскомментируйте
нужные строки и примените: `docker compose up -d`.

| Переменная | Что делает | Если не задана |
|---|---|---|
| `ADMIN_USERNAME` | логин администратора | `teacher` |
| `ADMIN_PASSWORD` | пароль администратора (от 12 символов) | случайный при первом запуске, в логе |
| `SECRET_KEY` | ключ подписи сессий и хешей флагов (от 32 символов) | случайный, хранится в томе `/data` |
| `WEB01_FLAG`, `WEB02_FLAG`, `CRYPTO01_FLAG` | флаги заданий | демонстрационные значения |

### Как поменять флаги перед турниром

1. Создайте `.env` из `.env.example` и задайте три флага в формате `CTF{латиница_цифры_-}`:

   ```
   WEB01_FLAG=CTF{ваш_флаг_1}
   WEB02_FLAG=CTF{ваш_флаг_2}
   CRYPTO01_FLAG=CTF{ваш_флаг_3}
   ```

2. Примените: `docker compose up -d`. Контейнеры пересоздаются, платформа при старте обновляет хеши флагов
   и заново создаёт файлы заданий WEB-02 и CRYPTO-01, лаборатория получает новый флаг WEB-01.

Демонстрационные флаги по умолчанию общеизвестны, поэтому для настоящего соревнования их обязательно нужно заменить.
Флаги синхронизируются по коду в начале названия задания (`WEB-01`, `WEB-02`, `CRYPTO-01`): если переименовать задание
так, что код пропадёт, платформа перестанет обновлять его флаг. `SECRET_KEY` после создания заданий менять нельзя:
от него зависят хеши флагов, и все флаги перестанут приниматься.

## Архитектура и безопасность

```
Браузер → Nginx (127.0.0.1:8080) ─┬─ /      → app (FastAPI + SQLite, volume db_data)   [app-net]
                                  ├─ /static/ → app (стили и файлы заданий)             [app-net]
                                  └─ /lab/  → lab-web (учебный WEB-01)                  [lab-net, internal]
```

### Две сети: зачем и почему это безопасно

Задание WEB-01 намеренно уязвимо, поэтому его нужно запереть так, чтобы взлом задания не давал доступа к платформе.

- **app-net**: Nginx и платформа. Наружу выходит только порт Nginx и только на `127.0.0.1`.
- **lab-net** (`internal: true`): Nginx и лаборатория. У этой сети нет выхода в интернет.

Контейнер `lab-web` подключён только к `lab-net`, поэтому он не видит платформу и её базу данных (нет общей сети и общего тома),
не имеет доступа в интернет и не получает Docker Socket. Общая точка у двух сетей только одна, Nginx, и он лишь передаёт запросы.
Дополнительные ограничения лаборатории: запуск не от root, корневая файловая система только для чтения (запись только в `/tmp`),
`cap_drop: ALL`, `no-new-privileges`, лимит 256 МБ RAM, 0.5 CPU и 100 процессов. Лаборатория получает только одну
переменную окружения, свой флаг. Если лаборатория остановлена или упала, Nginx отдаёт понятную страницу с кодом 503,
а платформа и рейтинг продолжают работать.

### Защита платформы

- пароли хранятся как **Argon2id**; флаги только как **HMAC-SHA256** (ключ `SECRET_KEY`) и нигде не показываются;
- **CSRF-токены** во всех формах, сессионные куки подписаны и имеют `SameSite=Strict`;
- права администратора проверяются **на сервере**, а не скрытием кнопок;
- баллы начисляются **один раз**: решение хранится с составным уникальным ключом (пользователь, задание),
  повторная отправка ничего не добавляет;
- **ограничение частоты**: 3 секунды между попытками на пользователя и задание, не больше 20 попыток в минуту на пользователя,
  а в Nginx общий лимит на `POST /login`, `/register` и отправку флагов (ответ 429);
- администратор при первом входе обязан сменить пароль; секреты (`SECRET_KEY`, пароль) не хранятся в репозитории;
- Swagger и OpenAPI отключены;
- флаги заданий после старта убираются из окружения веб-процесса платформы.

Ограничения: для недоверенных участников в реальной эксплуатации нужна дополнительная изоляция на уровне виртуальной машины;
HTTPS не используется, потому что сервис слушает только `localhost`; в Docker все участники приходят с одного адреса,
поэтому лимиты Nginx общие и щедрые.

## Тесты и проверка

```bash
pip install -r app/requirements.txt pytest httpx pyyaml    # один раз, лучше в виртуальном окружении
pytest -q                                                  # тесты backend, заданий, шаблонов и инициализации
python tests/check_stack.py                                # проверка запущенного стека (нужны Python 3 и Docker)
```

`check_stack.py` проверяет доступность, изоляцию лаборатории, остановку лаборатории, ограничение частоты и выводит
потребление ресурсов. После него вход на сайт около минуты отвечает 429: это следствие проверки.
Ручной чек-лист приёмки: `tests/ACCEPTANCE_CHECKLIST.md`.

### Потребление ресурсов (`docker stats`, платформа в покое)

| Сервис | RAM (использовано / лимит) | CPU |
|---|---|---|
| nginx | 2.7 МиБ / 64 МиБ | 2.65% |
| app | 54.6 МиБ / 512 МиБ | 0.18% |
| lab-web | 11.0 МиБ / 256 МиБ | 0.01% |

Замер сделан на предыдущей сборке, до автоматической инициализации. Ориентир из задания: не более 1–1.5 ГБ RAM.
После изменений повторите `docker stats --no-stream` и обновите таблицу.

## Платформы

Нужен только Docker, скрипты не используются.

- **Linux:** Docker Engine и плагин Compose (<https://docs.docker.com/engine/install/>), затем `sudo systemctl enable --now docker`
  и `sudo usermod -aG docker $USER` (потом перелогиниться).
- **macOS:** Docker Desktop. Образы поддерживают Intel и Apple Silicon.
- **Windows:** Docker Desktop с бэкендом WSL 2 (режим Linux-контейнеров). Команды выполняются в PowerShell, cmd, Git Bash или WSL.
  При клонировании `.gitattributes` сохраняет в конфигах и Python-файлах переводы строк LF.

## Структура репозитория

```
├── compose.yaml            сервисы nginx, app, lab-web, сети, volume, лимиты
├── .env.example            необязательные настройки (все строки закомментированы)
├── app/                    платформа: main.py, models.py, init_db.py, task_files.py, backup.py, templates/, static/
├── lab/                    уязвимое приложение WEB-01
├── nginx/nginx.conf        маршрутизация, ограничение частоты, страница 503
├── tests/                  автотесты, check_stack.py, чек-лист приёмки
└── docs/                   заметки по backend и описание дизайн-макета
```

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `docker: command not found` или `Cannot connect to the Docker daemon` | Docker не установлен или не запущен (Docker Desktop должен показывать «Engine running») |
| `port is already allocated` на 8080 | порт занят: остановите старую копию (`docker compose down`) или найдите процесс (`ss -ltnp \| grep 8080`, в Windows `netstat -ano \| findstr 8080`) |
| Не знаю пароль администратора | `docker compose logs app` (рамка в начале вывода); если уже менялся и забыт, полный сброс: `docker compose down -v` и `docker compose up -d --build` |
| `app` не запускается, в логе `ОШИБКА НАСТРОЙКИ` | значение в `.env` неверного формата: `SECRET_KEY` короче 32, `ADMIN_PASSWORD` короче 12 символов или флаг не в формате `CTF{...}` |
| После входа `Please change initial password` | сначала смените пароль на `/change-password` |
| Ошибка 429 при входе или отправке флага | сработало ограничение частоты, подождите около минуты |
| `/lab/` показывает 503 | контейнер лаборатории остановлен: `docker compose start lab-web`, причина в `docker compose logs lab-web` |
| Права на сокет Docker в Linux (`permission denied`) | нет группы `docker` или перелогина: `sudo usermod -aG docker $USER` (временно можно использовать `sudo`) |

Замечания по первоначальному дизайн-макету: [docs/DESIGN_MOCKUP.md](docs/DESIGN_MOCKUP.md).
