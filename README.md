# CYBERARENA

Учебная CTF-платформа для внутренних соревнований по информационной безопасности.
Преподаватель публикует задания, участники находят флаги формата `CTF{...}` и отправляют их на сайте,
система сама начисляет баллы и строит рейтинг. Всё работает на одном ноутбуке, без облака и внешних сервисов.

## Возможности

**Участник:** регистрация и вход, каталог заданий со статусом решения, страница задания с формой отправки флага,
личный кабинет с историей решений, таблица лидеров (при равенстве баллов выше тот, кто решил раньше).

**Преподаватель:** создание и редактирование заданий, публикация и скрытие, просмотр последних попыток,
сброс результатов турнира. Учётная запись создаётся при первом запуске из переменных окружения.

**Задания:**

| ID | Баллы | Категория | Суть |
|---|---|---|---|
| WEB-01 | 100 | Web | уязвимое приложение в изолированном контейнере (ошибка разграничения доступа) |
| WEB-02 | 150 | Web | анализ HTML и JavaScript учебной страницы |
| CRYPTO-01 | 150 | Crypto | расшифровка перехваченной записки |

## Стек

FastAPI, Jinja2, SQLAlchemy и SQLite, Argon2id, Nginx, Docker Compose.

## Требования

- Linux, macOS или Windows с Docker Engine и Docker Compose v2
- 8 ГБ RAM, 4 логических CPU, 10 ГБ свободного диска, свободный порт 8080
- Python 3 на хосте (нужен только `build_tasks.py`; `init-env.sh` обойдётся и `openssl`)
- интернет нужен один раз для сборки образов, после этого проект работает офлайн

## Установка Docker

**Linux.** Установите Docker Engine и плагин Compose по инструкции для вашего дистрибутива
(<https://docs.docker.com/engine/install/>), затем:

```bash
sudo systemctl enable --now docker.service
sudo usermod -aG docker $USER      # затем выйти из сессии и зайти снова
docker run hello-world             # проверка
docker compose version             # должен быть Compose v2
```

**macOS.** Установите Docker Desktop (<https://docs.docker.com/desktop/setup/install/mac-install/>) и запустите его.
Проверка в терминале: `docker run hello-world` и `docker compose version`.
Образы проекта (`python`, `nginx`) поддерживают и Intel, и Apple Silicon.

**Windows:** см. раздел «Запуск на Windows» ниже.

## Быстрый старт

```bash
./scripts/init-env.sh              # создаёт .env со случайными секретами, выводит пароль администратора
docker compose up -d --build       # собирает и запускает nginx, app, lab-web
./scripts/seed.sh                  # загружает три задания в базу
```

На Linux, пока группа `docker` не применилась (нужен перелогин), добавляйте `sudo` перед `docker` и перед `./scripts/seed.sh`.
Сам `init-env.sh` запускайте без `sudo`. На macOS и Windows `sudo` не нужен.

После запуска:

- платформа: <http://localhost:8080>
- лаборатория WEB-01: <http://localhost:8080/lab/> (открывается из карточки задания)

## Запуск на Windows

Контейнеры работают на Windows так же, как на Linux, но скрипты из `scripts/` написаны на bash.

1. Установите **Docker Desktop** с бэкендом **WSL 2** (режим Linux-контейнеров, он включён по умолчанию)
   и включите виртуализацию в BIOS, если Docker об этом попросит.
2. Выполняйте команды в **Git Bash** (идёт вместе с Git for Windows) или в терминале **WSL**, а не в cmd и PowerShell.
3. Клонируйте репозиторий как обычно: файл `.gitattributes` сохраняет в скриптах и конфигах переводы строк LF.
   Если скрипты уже скачаны с CRLF, ошибка выглядит как `bash\r: No such file or directory`: перекачайте репозиторий
   после `git config --global core.autocrlf input`.
4. Дальше те же три команды: `./scripts/init-env.sh`, `docker compose up -d --build`, `./scripts/seed.sh`.
   Вместо `python3` на Windows обычно доступен `python`: `python tasks/build_tasks.py`.
5. Проверку `nginx -t` удобнее делать уже после запуска: `docker compose exec nginx nginx -t`
   (команда с `docker run -v` в Git Bash искажает пути и требует `MSYS_NO_PATHCONV=1`).

`sudo` на Windows не нужен. Порт 8080 открывается только на `127.0.0.1`, то есть с этого же компьютера.
Docker Desktop занимает под WSL 2 заметную часть памяти, на ноутбуке с 8 ГБ закройте лишние программы.

## Учётная запись администратора

- логин и пароль задаются в `.env` (`ADMIN_USERNAME`, `ADMIN_PASSWORD`); `init-env.sh` ставит логин `teacher` и случайный пароль;
- при первом входе платформа требует сменить пароль (не короче 12 символов), новый пароль в `.env` не записывается;
- в репозитории паролей нет, `.env` исключён из Git (`.gitignore`);
- платформа не запустится, пока `SECRET_KEY` короче 32 символов, а `ADMIN_PASSWORD` короче 12.

## Управление

| Действие | Команда |
|---|---|
| Состояние сервисов | `docker compose ps` |
| Остановить / запустить | `docker compose stop` / `docker compose start` |
| Перезапуск (данные сохраняются) | `docker compose restart` |
| Логи (всех или одного сервиса) | `docker compose logs -f` / `docker compose logs -f app` |
| Убрать контейнеры (данные остаются) | `docker compose down` |
| Сбросить только результаты турнира | админка → «Сброс турнира» (ввести `RESET`) |
| Полный сброс: пользователи, решения, задания | `./scripts/reset.sh` (задания загружаются заново) |
| Резервная копия SQLite | `./scripts/backup.sh` (файл в `backups/`) |
| Потребление RAM и CPU | `docker stats --no-stream` |

Восстановление из резервной копии:

```bash
docker compose stop app
docker compose cp backups/<файл>.db app:/data/cyberarena.db
docker compose start app
```

Пользователи и результаты хранятся в Docker volume `db_data` и сохраняются после `docker compose restart`.

## Архитектура

```
Браузер → Nginx (127.0.0.1:8080) ─┬─ /static/ → файлы заданий WEB-02, CRYPTO-01 и стили
                                  ├─ /lab/    → lab-web (учебный WEB-01)           [lab-net, internal]
                                  └─ /        → app (FastAPI + SQLite, volume)     [app-net]
```

Две Docker-сети разделяют платформу и уязвимую лабораторию:

- **app-net**: Nginx и платформа. Наружу выходит только порт Nginx и только на `127.0.0.1`.
- **lab-net** (`internal: true`): Nginx и лаборатория. У сети нет выхода в интернет.

Контейнер лаборатории не подключён к `app-net`, поэтому не видит платформу и её базу, и не получает Docker Socket.
Он работает не от root, с read-only файловой системой (запись только в `/tmp`), `cap_drop: ALL`, `no-new-privileges`,
лимитом 0.5 CPU, 256 МБ RAM и числа процессов. Если лаборатория остановлена, Nginx показывает понятную страницу (503),
а платформа и рейтинг продолжают работать.

## Безопасность

- пароли хранятся как Argon2id; флаги только в виде HMAC-SHA256 хеша и нигде не показываются;
- CSRF-токены во всех формах, подписанные сессионные куки с `SameSite=Strict`;
- права администратора проверяются на сервере, а не скрытием кнопок;
- баллы начисляются один раз: решение хранится с составным уникальным ключом (пользователь, задание);
- ограничение частоты отправки флагов: 3 секунды на пользователя и задание в приложении плюс общий лимит в Nginx
  на `POST /login`, `/register` и отправку флагов (ответ 429);
- флаги заданий не попадают в окружение платформы: WEB-01 получает свой флаг только в контейнер лаборатории;
- Swagger и OpenAPI отключены.

Ограничения: в production для недоверенных участников нужна дополнительная изоляция на уровне виртуальной машины;
HTTPS не используется, потому что сервис слушает только `localhost`; в Docker все участники приходят с одного адреса,
поэтому лимиты Nginx общие и щедрые.

## Тесты и проверка

```bash
./scripts/check.sh                                              # инфраструктура, изоляция, отказоустойчивость, задания
python3 -m unittest discover -s tests -p "test_[ti]*.py" -v     # задания, шаблоны, загрузчик, стыки с backend
pytest -q                                                       # тесты backend (pip install -r app/requirements.txt pytest httpx)
```

После `check.sh` подождите около 40 секунд: скрипт проверяет ограничение частоты, и вход на сайт временно отвечает 429.
Ручной чек-лист приёмки (регистрация, решение, повторная отправка, сброс, работа без интернета): `tests/ACCEPTANCE_CHECKLIST.md`.

### Результаты `scripts/check.sh`

Стенд: CachyOS (Arch Linux), Docker Engine и Compose v2, платформа с тремя загруженными заданиями.

| Группа | Проверки | Результат |
|---|---|---|
| Доступность | платформа на :8080, лаборатория через `/lab/`, Nginx слушает только 127.0.0.1:8080, платформа не опубликована напрямую | OK |
| Изоляция лаборатории | не видит платформу, нет интернета, нет `docker.sock`, не privileged, read-only ФС, без host network, не от root | OK |
| Конфигурация | `nginx -t`, `SECRET_KEY` и `ADMIN_PASSWORD` не короткие и не заглушки, Nginx раздаёт `/static/` | OK |
| Задания и флаги | флаги не в окружении платформы и не на главной, WEB-01 решается через Nginx, файлы WEB-02 и CRYPTO-01 доступны | OK |
| Отказоустойчивость | лаборатория остановлена: `/lab/` отвечает 503 с понятной страницей, платформа отвечает 200 | OK |
| Ограничение частоты | серия `POST /login` получает 429 (24 из 45 запросов) | OK |

## Структура репозитория

```
├── compose.yaml            сервисы nginx, app, lab-web, сети, volume, лимиты
├── .env.example            шаблон настроек (реальный .env в Git не попадает)
├── app/                    платформа: main.py, models.py, templates/, static/, seed_challenges.py

├── nginx/nginx.conf        маршрутизация, статика, ограничение частоты, страница 503

├── tasks/                  генератор заданий (build_tasks.py) и описание
├── tests/                  автотесты и чек-лист приёмки
├── teacher/                материалы преподавателя (решения заданий), студентам не показывать
```

## Смена флагов перед турниром

Значения в `.env.example` демонстрационные. Замените три строки `*_FLAG` в `.env`, затем:

```bash
python3 tasks/build_tasks.py       # пересоздаёт файлы WEB-02, CRYPTO-01 и список заданий
docker compose up -d --build
./scripts/seed.sh                  # обновляет флаги в базе
```

Менять `SECRET_KEY` после загрузки заданий нельзя: от него зависят хеши флагов, и все флаги перестанут приниматься
(исправляется повторным `./scripts/seed.sh`).
Папку `teacher/` перед публикацией репозитория для студентов нужно убрать.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `required variable ... is missing` или `env file ... not found` | нет `.env` или в нём не хватает переменных: `./scripts/init-env.sh` |
| `app` не запускается, в логах `Configure SECRET_KEY (32+)...` | `SECRET_KEY` короче 32 или `ADMIN_PASSWORD` короче 12 символов |
| `failed to connect to the docker API ... no such file or directory` | служба Docker не запущена: `sudo systemctl enable --now docker.service` |
| `permission denied while trying to connect to the docker API` | пользователь не в группе `docker` или нет перелогина (временно `sudo`) |
| `port is already allocated` на 8080 | порт занят: `ss -ltnp \| grep 8080`; остановите старую копию проекта: `docker compose down` |
| В каталоге нет заданий | не выполнен `./scripts/seed.sh` |
| После входа `Please change initial password` | сначала смените пароль на `/change-password` |
| Ошибка 429 при входе или отправке флага | сработало ограничение частоты, подождите около минуты |
| `/lab/` показывает 503 | контейнер лаборатории остановлен: `docker compose start lab-web`, причина в `docker compose logs lab-web` |
| `Expected a string, but found a redirection` в fish | команда написана для bash; используйте готовые скрипты из `scripts/` |
