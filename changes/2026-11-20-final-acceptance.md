# CYBERARENA — финальная техническая приёмка, 20 ноября 2026

Исходное состояние: ветка `fix/acceptance-hardening`, HEAD `a206e32`, рабочее дерево уже содержало изменения. Рабочий экземпляр на `localhost:8080` ответил HTTP 200 перед началом. Оригинальное ТЗ — PDF «Кейс Школа 21(1)», §§2, 4–7, 10–12.

## Изменения

§2 описывает скрытие заданий, §5 требует CRUD, §10 проверяет создание либо редактирование и публикацию. Для буквального выполнения CRUD добавлено физическое удаление скрытых пользовательских карточек без попыток и решений. Встроенные карточки управляются при развёртывании. Скрытие карточек с историей сохраняет их решения, попытки и начисленные баллы. Проверки удаления и сама запись выполняются в одной транзакции SQLite, сериализованной с отправкой ответа и редактированием карточки. Удаление требует роли преподавателя, CSRF-токена и ввода `DELETE`.

- `app/main.py`, `app/templates/admin.html` — маршрут и форма удаления.
- `tests/test_backend.py`, `tests/test_integration.py`, `tests/compose_e2e.py` — проверки CRUD, сохранения истории и соответствия форм маршрутам.
- `tests/compose_e2e.py`, `tests/check_stack.py` — после восстановления лаборатории ожидают и Docker healthcheck, и HTTP. Это устраняет наблюдавшуюся гонку, при которой HTTP уже проходил, а Docker ещё сообщал `starting`.
- `README.md` — политика удаления, быстрый старт и отдельный порт при конфликте.
- `changes/2026-11-20-final-acceptance.md` — этот отчёт.

Перед правками сохранены копии изменяемых файлов и исходный Git-статус в `~/backups/cyberarena-final.vHwFvbnM`. Для отката скопируйте семь исходных файлов из резервной папки в те же пути репозитория, предварительно сверив более поздние правки. Если нужно убрать этот отчёт, удалите только его. ## Сценарий защиты на три минуты

- **0:00–0:30.** На демонстрационной машине выполните `docker compose up -d --build --wait` и `docker compose ps`. Откройте `http://localhost:8080`. Nginx принимает браузерные запросы и маршрутизирует их в FastAPI и WEB-лабораторию. FastAPI хранит участников, сессии, карточки, попытки и решения в SQLite на томе. У лаборатории отдельная внутренняя сеть и только свой ресурс для задания.
- **0:30–1:10.** В отдельном профиле войдите как участник. Откройте каталог и одно из заданий с опубликованными материалами, например CRYPTO-01. Получите ответ из материала, отправьте через форму и покажите запись в профиле.
- **1:10–1:40.** Откройте рейтинг, повторите сдачу спустя три секунды и покажите прежнюю сумму. При равенстве баллов выше участник с более ранним последним засчитанным решением.
- **1:40–2:30.** Войдите как преподаватель. Создайте отдельный черновик, измените карточку, опубликуйте, покажите её из учётной записи участника. Скройте карточку без попыток и удалите с подтверждением `DELETE`. В таблицах админки покажите прошлые попытки и решения.
- **2:30–3:00.** Покажите статистику контейнеров и рейтинг после штатного рестарта. Для полной репетиции отдельно зафиксируйте результаты трёх заданий и запуска на демонстрационной машине.

## Вопросы преподавателя

- **Как предотвращается повторное начисление?** SQLite сериализует транзакции записи. В таблице решений одна запись на пару «участник — задание». Рейтинг суммирует баллы по этим записям.
- **Что защищает административные операции?** Серверная проверка роли и сессии, CSRF-токен для POST, обязательная смена начального пароля. У удаления есть дополнительное подтверждение.
- **Что происходит с результатами скрытой карточки?** Участник теряет доступ к карточке из каталога. Существующие решения остаются в профиле и рейтинге.
- **Что происходит при падении лаборатории?** Nginx отдаёт понятный 503 для лаборатории. FastAPI обслуживает остальные страницы через другую сеть.
- **Что нужно для офлайн-запуска?** Заранее подготовленные образы с тегами проекта и локальный том. Запуск — `docker compose up -d --no-build --pull never --wait`.

## Восстановление запуска

На демонстрационной машине проверьте `docker compose ps -a` и `docker compose logs --tail 100 nginx app lab-web`. При конфликте порта используйте отдельный Compose-проект с другим свободным loopback-портом по README. При исправлении ошибки повторите `docker compose up -d --build --wait` в том же демонстрационном проекте. При прошлом успешном запуске повторите старт из готовых образов без сети. Для повреждённой базы восстановите проверенную SQLite-копию в отдельный пустой том по инструкции README и проверьте результаты перед переключением. Команда `down -v` удаляет тома, поэтому для обычного восстановления используйте restart или up с тем же проектом.

## Команды воспроизведения

В каталоге проекта установите зависимости тестов в отдельное виртуальное окружение по README. Для испытаний Docker выберите отдельный движок или отдельный тестовый Compose-проект и свободный loopback-порт. E2E проверяет, что у проекта ещё нет контейнеров или томов.

```bash
python -m pytest -q -k 'not test_idor_reveals_flag and not test_other_users_note_is_open_too and not test_unknown_paths_do_not_leak_files and not test_raw_dotdot_request_is_not_served'
docker compose --env-file /dev/null config -q
docker compose --env-file .env.example config -q
node --check tests/check_browser.mjs
firefox --headless --no-remote --profile "$(mktemp -d)" --remote-debugging-port 19227 about:blank
# Следующие команды выполняются во втором терминале.
python tests/compose_e2e.py --project cyberarena-test-defense --port 18127 --firefox-bidi 19227
python tests/check_stack.py --project cyberarena-test-defense --base http://127.0.0.1:18127 --stop-lab
docker compose -p cyberarena-test-defense stats --no-stream
git diff --check
```

Для проверки штатного порта на отдельном хосте или в отдельном сетевом пространстве выполните команды быстрого старта из README, затем `curl -fsS http://localhost:8080/health` и `curl -fsS http://localhost:8080/lab/health`. Для проверки офлайн используйте только отдельную среду. После подготовки образов отключите её внешнюю сеть и повторите запуск `docker compose up -d --no-build --pull never --wait`. Для проверки сохранности используйте `docker compose stop` и `docker compose start --wait` в испытательном проекте, сравните рейтинг до и после.
